# SIST™ — Public Methodology Overview

This document is the current public high-level methodology reference for SIST™.

SIST is an independent AI research and intelligence-analysis platform built around structured records, multiple analytical perspectives, adversarial examination, source-grounded synthesis, and human-controlled deployment.

## Canonical public operating pipeline

The current public operating model uses nine stages:

1. **INTAKE** — define the objective, scope, actors, constraints, and record boundary.
2. **LIBRARIAN** — normalize, index, and preserve the source record and provenance.
3. **INGESTOR** — extract facts, claims, dates, entities, contradictions, and evidence gaps.
4. **RESEARCHER** — develop missing context, external sources, authorities, and expected evidence.
5. **ANALYST** — build timelines, relationships, competing explanations, and critical findings.
6. **LAWCLERK** — test rules, standards, procedure, authority, and decision relevance where required.
7. **COUNTERMEASURES** — attack the working position for weak links, contradictions, alternate explanations, and failure paths.
8. **BRIEFER** — convert surviving findings, uncertainty, and options into a usable intelligence product.
9. **DEPLOY MASTER** — release only what survives the record, challenge, and human-controlled deployment gate.

## Control gates

The public architecture presents five control gates:

- **G1 — Intake**
- **G2 — Ingestion**
- **G3 — Intelligence**
- **G4 — Adversarial**
- **G5 — Deployment**

A gate is a control point, not a decorative progress marker. Findings can be revised, held, replaced, superseded, withdrawn, or otherwise prevented from advancing when the record does not support release.

## Human authority

SIST is decision support. Human authority remains responsible for objectives, judgment, approval, and consequential action. No AI seat has final authority.

## Public principle

**Information should be challenged before it is treated as deployable intelligence.**

## What is intentionally omitted

This public document does **not** disclose proprietary prompts, model-selection logic, routing heuristics, thresholds, private schemas, credentials, private integrations, or other confidential implementation details.

The public operating model describes real implemented functions without serving as a reconstruction guide for the private system.

## Validation boundary

The public materials do not claim zero-error operation, universal superiority over single-model systems, or statistical proof across every domain. Those are validation questions that should be measured rather than assumed.
